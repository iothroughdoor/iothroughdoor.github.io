A practical guide to implementing hierarchical 𝝁arch analysis

Introduction

When seeking to improve the performance of a program, the metric that matters in the end is the execution time. However, in order to decrease this execution time we may want to analyse the micro execution steps of the micro architecture when it is not obvious how execution time can be reduced.

Yasin [1] described a pragmatic approach - oriented on the nature of CPU 𝝁arch - to guide performance improvement. Although CPU manufacturers provide their own tools for performance analysis (AMD's 𝝁Prof or Intel's VTune), these tend to have their special ways of presentation and and their special focus. Wouldn't it be nice to have a common tooling for all kinds of CPUs?
In this article, I'll explain the simple setup I often use and how you can built on it whatever you may further need.

Preliminaries

First, let me clarify that the hierarchical analysis requires you to already know which part of the software you want to look at; or, in other words, you need to have a micro benchmark that you can analyze. We don't discuss here how to get there.

Let us first review the basic components of a micro architecture of modern CPUs. On the intel website [2], you can find a typical block diagram for x86 CPUs. The documentation of the ARM Cortex-A72 [3] describes a similar picture. So on this coarse level of micro architecture, ARM and x86 CPUs are actually very similar. Let us first examine the typical structure of an x86 CPU. Figure 1 depicts clearly a distinction between a frontend and a backend part.

Figure 1: Typical x86 micro architecture; taken from [2]

A typical, somewhat simplified procedure conducted by the frontend is as follows
  1. The branch predictor / branch prediction unit determines the next instruction to be fetched.
  2. When the request to the L1 instruction cache is finished and the instruction loaded, one of many decoders takes care of the op code and translates it into (possibly multiple) micro operations that are enqueued in a micro operation queue for the backend to process.
